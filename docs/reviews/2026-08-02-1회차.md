# 1. 현재 완성도

## 게임으로 성립하는가 — **아니오, 아직**

코어 루프(이동 → 자동사격 → 처치 → 오브 → 레벨업 → 증강)는 확실히 돌아갑니다. 웨이브·보스·시대 전환까지 뱀서라이크 **골격**은 갖췄습니다. 그런데 결정적인 게 없습니다.

> **게임오버가 없습니다.**
> `Health`가 `IsDead`를 세우고 `PlayerMove`/`AutoAimShooter`가 멈추는 게 전부입니다. 적은 계속 스폰되고, 타이머는 계속 돌고, 화면은 그대로입니다. 플레이어는 죽은 채로 화면을 보고만 있게 됩니다. 재시작도 없어서 **브라우저 새로고침이 유일한 탈출구**입니다.

이건 "부족한 기능"이 아니라 게임의 마지노선입니다. 심사자가 첫 판에 죽으면 그 자리에서 멈춥니다. 최우선입니다.

같은 급으로 없는 것: **타이틀 화면 없음** (로드되자마자 시작, WASD·자동사격이라는 안내 없음), **클리어 화면 없음** (`OnGameClear`는 이벤트만 발행하고 구독자가 없습니다).

## 30~60초 영상에 담을 게 충분한가 — **아슬아슬합니다**

**쓸 수 있는 것**: 시대 전환 연출(페이드 + 배너)이 유일하게 "오" 소리 나는 장면입니다. 보스 돌진·충격파, 증강 카드 선택, 다중사출 5발이 그다음입니다.

**비어 보이는 구간** — 냉정하게:

- **초반 20~30초**: 적 1~2마리, 화면이 텅 빕니다. 영상에 넣을 수 없는 구간입니다.
- **전 구간**: 배경이 단색이라 모든 컷이 밋밋합니다. 컷을 아무리 잘 붙여도 화면이 심심합니다.

- **무음**: 후반작업으로 BGM·SFX를 얹어야 하는데, 그러면 "게임에 소리가 없다"는 게 오히려 티납니다.

**배경 타일/그리드를 까는 게 영상 체감 개선 대비 비용이 제일 쌉니다.** 1~2시간이면 되고 효과는 사운드 다음으로 큽니다.

# 3. 기술적 리스크

## WebGL에서만 터질 코드 — 금지 API는 깨끗합니다

`System.IO`·스레딩·소켓 전부 없습니다. `Keyboard.current` null 체크도 `PlayerMove`/`WaveManager`/`EraManager` 모두 되어 있습니다. CLAUDE.md 제약을 잘 지켰습니다.

다만 **빌드에 치명적인 게 하나 있습니다**:

> **디버그 키가 빌드에 살아 있습니다.**
> `WaveManager`의 **B키**(즉시 보스 소환)와 `EraManager`의 **N키**(즉시 시대 전환)가 `Update()`에서 무조건 돌아갑니다. `#if UNITY_EDITOR`도, 플래그도 없습니다.
> 심사자가 WASD 근처를 더듬다 **B를 누르면 보스가 튀어나오고, N을 누르면 시대가 스킵됩니다.** 게임이 망가진 것처럼 보입니다. 15분이면 막습니다.

사소한 것 하나 더: `Health.InvincibilityRoutine`이 `WaitForSeconds`(스케일 적용)를 쓰는데 증강 카드가 `timeScale=0`을 겁니다. 무적 중 레벨업하면 카드를 고를 때까지 무적이 안 풀립니다. 카드를 고르면 재개되니 실질 피해는 거의 없습니다.

## 빌드 13MB 구성 — **원인이 명확하고, 크게 줄일 수 있습니다**

```
Build.wasm.br   7.2MB   ← 코드. 여기가 문제
Build.data.br   4.8MB   ← 에셋 + 씬
framework.js.br  76KB
loader.js        28KB
```

에셋은 스프라이트 2장·폰트 1개·SO 8개가 전부인데 **data가 4.8MB, wasm이 7.2MB**입니다. 안 쓰는 패키지가 통째로 실려 있기 때문입니다.

`Packages/manifest.json`에서 **코드에서 단 한 번도 참조하지 않는** 것들:

| 패키지 | 비고 |
|---|---|
| **`com.unity.ai.inference` (Sentis) 2.6.1** | 빌드 경고 수십 개의 출처. 셰이더를 잔뜩 굽습니다. **가장 큰 용의자** |
| `com.unity.visualscripting` | 미사용 |
| `com.unity.timeline` | 미사용 |
| `com.unity.2d.animation` / `aseprite` / `psdimporter` / `spriteshape` / `tilemap.extras` | 흰 사각형 2장만 쓰는데 전부 들어있음 |
| `modules.physics`(3D) / `terrain` / `terrainphysics` / `vehicles` / `cloth` / `vr` / `xr` / `wind` / `umbra` / `video` / `vectorgraphics` / `adaptiveperformance` / `androidjni` | 전부 미사용 |

경험적으로 Sentis + VisualScripting + Timeline + 안 쓰는 modules를 걷어내면 **wasm이 30~50% 줄어듭니다.** Player Settings의 Managed Stripping Level도 점검 대상입니다.

⚠️ **단, 5번(AI 훅)에서 Sentis를 쓸 계획이라면 Sentis는 빼면 안 됩니다.** 이 결정이 먼저입니다.

## 저사양 브라우저에서 프레임이 죽는 지점

가장 위험한 조합은 **6웨이브 후반 + 연사·다중사출 증강 풀스택**입니다.

1. **풀링 없음** (AI_LOG에 의도적 결정으로 기록됨). 다중사출 5발을 짧은 `fireInterval`로 쏘면 초당 20~25발이 `Instantiate` → `Destroy`됩니다. 여기에 적 40마리 + 오브까지. **WebGL은 단일 스레드라 GC 스파이크가 그대로 프레임 끊김으로 보입니다.**
2. **`AutoAimShooter.FindNearestEnemy()`가 발사마다 `FindGameObjectsWithTag`로 배열을 할당합니다.** 주석엔 "발사 주기당 1회라 충분하다"고 되어 있는데, 연사 증강이 쌓이면 `fireInterval`이 0.2초 밑으로 내려갑니다. 초당 5~10회 배열 할당입니다.
3. `Enemy.Start()`와 `ExpOrb.Start()`가 **스폰될 때마다** `FindGameObjectWithTag("Player")`를 부릅니다.
4. 보스 충격파 8발이 주기적으로 추가됩니다.

**먼저 실측하세요.** 저사양 노트북 브라우저에서 6웨이브까지 가서 프레임을 재고, 실제로 죽을 때만 손대는 게 맞습니다. 풀링은 사실상 리팩터링이라 마감 6일 전에 시작할 작업이 아닙니다.

# 5. 인게임 AI 훅 — 여기가 승부처입니다

## 지금 구조에 붙이기 쉬운가 — **예, 매우 쉽습니다**

이건 진심으로 좋은 소식입니다. 적응형 디렉터가 필요한 **"읽을 신호"와 "돌릴 손잡이"가 이미 전부 public으로 열려 있습니다.**

**읽을 신호 (이미 존재)**
- `GameManager`: `Level` · `KillCount` · `SurvivalTime` · `ExpRatio`
- `Health.OnDamaged` / `OnDeath` → 피격 빈도·최근 데미지 계산 가능
- `WaveManager.CurrentWave`, `EraManager.CurrentEra`
- `EnemySpawner.AliveCount`, `OnEnemySpawned`

**돌릴 손잡이 (이미 존재)**
- `EnemySpawner.SpawnInterval` · `MaxAlive` (public setter) · `SetEnemyPrefab()`
- `Health.SetMaxHp()` — 스폰 직후 체력 스케일링 훅이 `OnEnemySpawned`에 이미 붙어 있음
- `WaveManager.ConfigureBoss()` · `ResetForNewEra()`
- `AutoAimShooter` / `PlayerMove`의 배율 프로퍼티

**즉, 기존 코드를 한 줄도 안 고치고 `AnomalyDirector.cs` 한 개만 추가하면 됩니다.** 오늘 만든 `EraManager`가 `WaveManager.OnBossDefeated`를 구독한 것과 똑같은 패턴입니다. 리팩터링 불필요 — 이 프로젝트가 이벤트 기반으로 짜여 있던 게 여기서 배당금을 냅니다.

## 더 나은 접근 — 두 가지를 짚겠습니다

### ① 가장 흔한 실패: **보이지 않는 AI**

적응형 디렉터를 만들어놓고 내부에서 `spawnInterval`만 조용히 조절하면, **심사자는 AI가 있는지 알 수 없습니다.** 난이도가 좀 달라진 것과 구분이 안 됩니다. 배점을 못 받습니다.

그래서 **디렉터의 판단을 화면에 드러내세요.**

```
시간 이상 감지 — 과잉 화력
└ 균열 증폭: 적 밀도 +40%
```

기존 `BossBannerUI`를 그대로 재사용할 수 있습니다(`Show(string)` 하나면 됩니다). "시간 이상"이라는 기획서 세계관이 **AI의 판단을 설명하는 장치**로 딱 맞아떨어집니다 — 게임 픽션과 기술 데모가 같은 것을 가리키게 됩니다. 이게 이 아이디어의 진짜 강점입니다.

덤으로: 디렉터가 내린 판단을 `[신호 → 판단 → 개입]` 형태로 로그에 남기고 그 로그를 제출물 4번에 붙이면, **AI 활용 문서가 코드 설명이 아니라 실측 데이터가 됩니다.**

### ② Sentis(ML) vs 규칙 기반 — **규칙 기반을 권합니다**

`com.unity.ai.inference`가 이미 설치돼 있어서 유혹이 있을 겁니다. 아이러니하게도 **지금 그 패키지는 쓰이지도 않으면서 빌드 13MB의 상당 부분을 차지하고 있습니다.**

D-8에 학습 데이터 수집 → 모델 학습 → 추론 통합 → WebGL 검증까지는 리스크가 너무 큽니다. 오늘 폰트 하나로 반나절을 썼습니다. 규칙 기반 디렉터를 **잘 설계하고 잘 보여주는 쪽**이 같은 시간에 훨씬 높은 점수를 받습니다.

⚠️ **다만 이건 제가 대회 규정을 몰라서 확실히 말할 수 없는 부분입니다.** "게임 AI 해커톤"에서 **AI가 개발 도구로서의 AI(Claude Code 활용)를 뜻하는지, 인게임 ML 모델을 뜻하는지**에 따라 답이 완전히 갈립니다.

- 전자라면 → AI_LOG가 이미 최고의 무기입니다. 규칙 기반 디렉터로 충분합니다.
- 후자에 ML 모델이 **필수 요건**이라면 → 규칙 기반은 감점 사유일 수 있고, Sentis 통합을 지금 시작해야 합니다.

**요강을 다시 확인하고 알려주시면 5번 계획을 그에 맞춰 구체화하겠습니다.** 이게 남은 8일 중 가장 큰 분기점입니다.

## 정리

**지금 당장**: 디버그 키 차단(15분) → 게임오버·재시작(3h). 이 둘이 없으면 나머지가 의미 없습니다.

**가장 저평가된 리스크**: 게임오버 부재와 B/N 디버그 키. 둘 다 "심사자가 만지는 순간" 드러납니다.

**가장 저평가된 기회**: 코드가 이벤트 기반이라 AI 디렉터를 **기존 코드 수정 없이** 얹을 수 있다는 점. 그리고 "시간 이상"이라는 세계관이 AI 판단을 설명하는 장치로 그대로 쓰인다는 점.

**확인이 필요한 것 2가지**: ① 5종 제출물의 정확한 목록 ② 대회가 요구하는 "AI"의 정의.
