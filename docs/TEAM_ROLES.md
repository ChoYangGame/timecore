## 개발 담당 — 역할 및 담당 영역

### 게임 설계 및 개발 스코프 관리

'시간관리국'이라는 세계관 위에서 한 판 5분 안팎의 생존 액션이라는 목표를 세우고,
남은 일정을 역산해 구현 범위를 조정했습니다. 마감 10일 전 시점에는 4시대를 2시대(원시·중세)로 축소하고
맵 기믹·아이템 슬롯을 삭제했으며, 코어 루프가 안정된 뒤 다시 4시대(원시·중세·현대·미래)로 확장했습니다.
"확장 가능한 구조"보다 **정해진 기간 안에 실제로 돌아가는 것**을 우선순위로 삼았습니다.

### 코어 게임플레이 시스템 구현

이동·자동 조준 사격·적 스폰·웨이브·경험치·레벨업·증강 선택으로 이어지는 생존 액션의 코어 루프를
직접 설계하고 구현했습니다. 증강은 공용 8종 + 직업 전용 15종(총 23종)이며,
총잡이·칼잡이·매지션 3개 직업이 각각 다른 공격 판정 구조(투사체 / 근접 호 / 지속 피해 지대)를 갖도록 분리했습니다.
스크립트 55종·약 1만 1천 줄 규모입니다.

### 시대 전환 구조와 콘텐츠 설계

시대가 바뀔 때 맵·적·필드 기믹·보스·BGM이 통째로 갈리는 구조를 만들었습니다.
보스 처치 후 아레나 중앙에 모래시계가 나타나고 그것을 획득해야 다음 시대로 넘어가는 게이트 방식으로,
전환을 자동 진행이 아닌 **플레이어의 행동**으로 만들었습니다.
시대별 필드 기믹(지면 균열 / 전기 방전 / 십자 폭격 / 레이저 격자)과 보스 4종 × 전용 패턴 3개(총 12패턴)를
"압박의 출처가 시대마다 달라야 한다"는 기준으로 설계했습니다.

### AI 디렉터(적응형 난이도) 설계 및 구현

기획서의 '시간 이상' 개념을 규칙 기반 적응형 디렉터(`AnomalyDirector`)로 구현했습니다.
5초마다 처치 속도 ÷ 스폰 속도, 체력 비율, 피격 빈도, 적 밀집도를 읽어
위기·과잉 화력·정체 세 규칙 중 하나로 판단하고 스폰 밀도나 난입 적으로 개입합니다.
**조용히 난이도만 조절하면 플레이어가 AI의 존재를 알 수 없으므로 개입은 항상 화면 배너와 함께 나가도록** 설계했고,
판단 근거를 콘솔 로그로 남겨 실제 플레이 완주 기록으로 동작을 검증했습니다.
외부 의존성 없는 순수 C# 규칙 기반이라 WebGL 빌드 용량에 영향을 주지 않습니다.

### AI 페어 프로그래밍 워크플로 구축

Claude Code와 Unity MCP를 연결해 코드 작성부터 씬 배선·Play 모드 실측·콘솔 검증까지 이어지는
개발 파이프라인을 직접 구성했습니다. 반복해서 사고를 유발한 규칙(에디터 실행 중 씬 파일 외부 편집 금지,
TMP 폰트 재굽기 절차, 컴파일 확인 경로 등)은 프로젝트 규칙 문서(`CLAUDE.md`)로 고정해
같은 실수가 재발하지 않도록 만들었습니다.
AI가 낸 오진(HP바 미동작을 셰이더 호환성 문제로 오판, 카메라 클램프 원인 오판 등)은
직접 에디터를 열어 근본 원인을 특정하고 방향을 바로잡았습니다.

### 아트·사운드 에셋의 게임 내 통합

디자인 담당이 제작한 스프라이트를 게임에 반영하는 전 과정을 담당했습니다.
낱장 PNG를 프레임 순서대로 스프라이트 애니메이션으로 구성하고, 유닛 크기·기준점을 통일했으며,
**그림과 판정이 어긋나지 않도록** 히트박스를 아트 기준으로 다시 맞췄습니다.
(예: 칼잡이는 참격 이펙트를 버리고 무기 그림 자체를 히트박스로 사용하도록 재설계)
BGM은 시대 전환 시 1초 크로스페이드로 교체되게 하고, 효과음 16종은 오디오 파일 없이
파형을 코드로 합성해 **빌드 용량 증가 0바이트**로 처리했습니다.

### UI·UX 구현

HUD(체력·경험치·레벨·웨이브·타이머·킬 수), 타이틀·직업 선택·결과·일시정지 화면,
증강 카드 UI, 보스 체력바·등장 배너를 구현했습니다.
한글 표시를 위해 TMP SDF 서브셋 폰트를 관리했고(라이선스 문제로 맑은 고딕 → Pretendard 전면 교체),
증강 카드와 보스 배너처럼 동시에 뜰 수 있는 UI에는 표시 우선순위 규칙을 두어 충돌을 정리했습니다.

### 온라인 랭킹 구현

로그인 없이 이름만 입력하는 io게임식 랭킹을 Vercel 서버리스 함수 + Upstash Redis로 구현했습니다.
게임과 **같은 도메인**에 API를 올려 WebGL 리더보드가 깨지는 1순위 원인인 CORS를 구조적으로 제거했고,
정렬 기준 두 개(도달 시대 · 시간)를 한 점수로 접어 sorted set 하나로 처리했습니다.

### WebGL 빌드·배포 파이프라인 및 용량 최적화

Unity WebGL 빌드부터 Vercel 프로덕션 배포까지의 파이프라인(`deploy.bat`)을 구성하고
Brotli 압축 헤더까지 실측 검증했습니다.
**빌드 용량 = 로딩 시간**이라는 제약 아래 모든 에셋 반입에 근거를 두고 판단했습니다.
(BGM 4곡 6.4MB → 모노·Vorbis 재인코딩으로 2.0MB, 메인 배경 1.8MB → 4의 배수 해상도로 리사이즈해 DXT1 450KB,
효과음은 파일 대신 코드 합성, 이펙트는 파티클 시스템 대신 풀링 조각)

### 검증·기록 및 제출 문서 관리

모든 구현을 추정이 아니라 Play 모드 실측 수치로 확인했습니다.
(예: 다중 사출 상한 검증 — 총알 645발 = 129볼리 × 5발 / 효과음 16클립 파형 전량 측정)
성공한 결정뿐 아니라 **실패한 시도·되돌린 결정·오진단까지 개발 로그(`docs/AI_LOG.md`)에 남겼고**,
외부 에셋·폰트는 도입 즉시 라이선스와 함께 출처 표에 기록해 제출 문서의 근거로 삼았습니다.

### 최종 역할

게임 설계와 스코프 관리부터 코어 시스템·AI 디렉터·UI·랭킹 서버 구현,
아트·사운드 에셋의 게임 내 통합, WebGL 빌드 최적화와 배포, 검증과 개발 문서화까지
**AI 페어 프로그래밍 기반의 게임 개발 전 과정**을 담당했습니다.

## 디자인 담당 — 역할 및 담당 영역

### 게임 전체 아트 방향 설정

'시간관리국' 세계관과 원시·중세·현대·미래의 시대별 콘셉트를 바탕으로
맵, 캐릭터, 몬스터, 보스의 디자인 방향을 기획했습니다.

### 2D 게임 에셋 제작

생성형 AI를 활용하여 맵, 플레이어 캐릭터, 몬스터, 보스, 무기, 공격 효과 등
게임에 필요한 주요 2D 아트 에셋을 제작했습니다.

### AI 이미지·영상 생성 및 프롬프트 설계

캐릭터의 시점, 방향, 비율, 크기, 배경, 광원, 그림자 등 게임 스프라이트 제작에 필요한 조건을
구체적으로 설계하고, 결과물을 반복 수정하며 일관된 스타일을 구축했습니다.

### 캐릭터·몬스터 애니메이션 제작

AI 영상 생성을 활용해 이동 및 공격 동작을 제작하고,
영상에서 자연스러운 움직임이 연결되는 프레임을 선별하여 스프라이트 애니메이션으로 구성했습니다.

### 무기 및 공격 모션 제작

권총, 근접 무기, 장판 공격용 무기 등을 개별 에셋으로 분리하고,
반동·회전·휘두르기 등 각 무기에 적합한 애니메이션 프레임을 제작했습니다.

### Unity 적용을 위한 에셋 최적화 및 관리

모든 결과물을 투명 PNG로 정리하고 크기와 기준점을 통일했으며,
프레임 순서, 반복 방식, 권장 애니메이션 속도 등을 체계적으로 관리했습니다.

### 최종 역할

생성형 AI를 활용한 2D 게임 아트 디렉팅부터 에셋 제작, 애니메이션 프레임 구성,
스프라이트 정리 및 Unity 적용까지 **전체 AI 기반 2D 아트 제작 파이프라인**을 담당했습니다.

## 협업 방식

| 접점 | 디자인 | 개발 |
|---|---|---|
| 아트 파이프라인 | 콘셉트 설계 → AI 생성 → 프레임 선별 → 투명 PNG 정리 (크기·기준점 통일) | 프레임 배선, 유닛 크기 환산, 히트박스 정합, 임포트 압축 설정 |
| 사운드 | 시대별 BGM 4곡 제작 | 반입·재인코딩(용량), 시대 전환 크로스페이드, 효과음 16종 코드 합성 |
| UI | 메인 화면 배경 아트 | 레이아웃·폰트·오버레이 밸런스, 화면 비율 대응 |
| 콘셉트 합의 | 시대별 비주얼 톤 | 시대별 게임플레이 성격(적 밀도·기믹·보스 패턴) |

- **스코프 축소·확장 결정은 두 사람이 함께 합의**했습니다 (4시대 → 2시대 축소 후 재확장).
- 아트는 "완성 에셋을 받아 그대로 붙인다"가 아니라, 받은 그림에 맞춰 **게임 쪽 판정과 연출을 다시 맞추는** 방식으로 통합했습니다.
- 작업 기록은 매 세션 `docs/AI_LOG.md`에 누적했고, 담당 구분(개발/디자인)을 항목마다 표기했습니다.
